\subsection{RAG pipeline}

The RAG pipeline has built by some component such as Search, prompt builder, and....
in this section we go into these sections and explain the reasons of every choice made. 

\subsection{Search}
A text search has a big role in RAG pipeline because finding a good content and provide them to LLM make the result
very consistent, and with fewer hallucinations. 
In the thesis we use two type search for getting better results, vector search and string match search. 
Combining these two methods provide us a hybrid method which have goods of two methods alone.
\subsubsection{Vector search}
After constructing the dataset, we need to retrieve related information for our RAFT pipeline.
By default, MathHub offers a robust text-based search system; however, it does not support vector-based search.
Which the vector search functionality were necessary to enable semantic search over the content of MathHub.
So we retrieved content from the URLs of the Mathhub and build the vector database to querying
the content.

On this way I experiment with multi embedding models to see how it can change the result of querying.
The result indicated that the increasing the dimensions of the vector over 1000 can backfire
and yielding to poor result.

\subsubsection{String match search}
MathHub provides text search function, however the text search has a big problem. It is a pure text search
which means only performs an exact string matching not a keyword finding from user query.
On the other hand, the user asks questions which contain not saying a keyword to explain it.

For example the user input is  "what is a NP hard problem means?" so the pure text search will retrieve not
related content with low score because the text search need only the "NP hard" keyword.

This problem motivated me to develop a keyword extractor mechanism from the user input and apply the text search
on extracted keyword.
