    \begin{itemize}
        \item \textbf{Simple Idea:} A program is a set of step-by-step instructions that a computer follows to perform a task.

    \end{itemize}

    \textbf{3. What is a "Goal" or "Objective"?}

    \begin{itemize}
        \item \textbf{Simple Idea:} Every task needs a finish line. If you go for a walk, your goal might be to reach the park.
        \item \textbf{What it means:} In technology, an AI Agent needs a specific goal to achieve (e.g., "Book me a flight to London" or "Keep the temperature at 72 degrees").
    \end{itemize}

    \textbf{Now, Let's Define "AI Agent"}

    Now that we have the building blocks (AI, Instructions, Goals), we can put them together!

    \begin{quote}
        \textbf{An AI Agent is basically a smart computer program that can \textit{sense} its environment, \textit{think} about what to do based on its goal, and then \textit{take action} to get closer to that goal, all by itself.}
    \end{quote}

    \textbf{Analogy: A Smart Robot Cleaner}

    Imagine a robot vacuum cleaner:

    \begin{enumerate}
        \item \textbf{Sense (Perceive):} It has sensors that "see" the dirt, walls, and furniture in the room. (This is the input from the environment.)
        \item \textbf{Think (Process):} It runs an AI program that thinks: "Goal is to clean the whole floor. I see dirt here, so I should go there." (This is the "brain" deciding what to do.)
        \item \textbf{Act (Execute):} It moves, sucks the dirt, and changes direction. (This is the output/action.)
    \end{enumerate}

    The key difference between a simple program and an AI Agent is \textbf{autonomy} (self-control).

    \begin{itemize}
        \item \textbf{Simple Program:} You have to tell it \textit{every single move}. ("Move forward 1 foot. Turn 90 degrees. Suck dirt.")
        \item \textbf{AI Agent:} You just tell it the \textit{goal}. ("Clean the whole room.") It figures out the steps on its own!

    \noindent\textbf{Prerequisites Review}

    To understand how good search heuristics are found, we must first define the core concepts: Search Problem, Heuristic Function, Admissible Heuristics, and Relaxed Problems.

    \begin{enumerate}

        \item \textbf{What is a Search Problem?}

              A search problem ($\Pi$) defines a task that an intelligent agent needs to solve by moving from a starting point to a goal. Formally, it consists of five components: the set of states ($\mathcal{S}$), the set of actions ($\mathcal{A}$), the transition model ($\mathcal{T}$), the initial state ($\mathcal{I}$), and the set of goal states ($\mathcal{G}$). A solution to this problem is a sequence of actions (a derivation $d$) that starts in $\mathcal{I}$ and ends in one of the goal states $\mathcal{G}$.

        \item \textbf{What is a Heuristic Function?}

              In search problems, the heuristic function ($h$) serves as an estimate or guide for the agent. It takes a state ($n$) from the set of all possible states ($\mathcal{S}$) and estimates the cost or distance from that specific state $n$ to the nearest goal state $\mathcal{G}$. The output value is always non-negative, meaning it cannot be negative (though it can be infinite if a goal is unreachable).

        \item \textbf{What are Admissible Heuristics?}

              An admissible heuristic is considered reliable because it never overestimates the true cost to reach the goal. For a search problem $\Pi$, a heuristic $h$ is admissible if, for every state $s \in \mathcal{S}$, its estimated cost $h(s)$ is less than or equal to the actual optimal cost-to-go, denoted as $h^*(s)$. This property ensures that the heuristic remains optimistic about finding the shortest path.

        \item \textbf{What are Relaxed Problems?}

              A relaxed problem ($\Pi^r$) is a modification of the original search problem ($\Pi$). It is created by relaxing certain constraints, such as restricting the set of available actions or simplifying the transition model, while keeping the states and goals intact. A key requirement for this relaxation is that all components must be subsets of the corresponding components in the original problem (e.g., $\mathcal{A}^r \subseteq \mathcal{A}$).

    \end{enumerate}

    \medskip

    \noindent\textbf{Finding Good Search Heuristics}

    The question asks how we can find a good search heuristic, specifically an \emph{admissible} one.

    Finding a highly accurate and admissible heuristic is often considered an art because it requires deep domain knowledge---meaning the designer must already have extensive understanding of the problem space to create an effective estimate. However, when domain knowledge is limited, researchers resort to computational techniques that allow them to ``cheat'' by leveraging simplified versions of the problem.

    \medskip

    \noindent\textbf{The primary method for finding good admissible heuristics is through the use of relaxed problems.}

    \begin{itemize}
        \item Relaxing a search problem makes it computationally easier to solve because fewer constraints need to be satisfied.
        \item By solving this simpler, \textbf{relaxed problem}, we can derive solutions and associated costs that provide a lower bound on the true optimal cost of the original problem.
        \item Since these derived costs are guaranteed to be less than or equal to the true minimal cost, they inherently satisfy the condition for admissibility ($h(s) \le h^*(s)$).
        \item Therefore, by constructing and solving various relaxed problems, we can systematically generate admissible heuristics that guide the search agent effectively.
    \end{itemize}
